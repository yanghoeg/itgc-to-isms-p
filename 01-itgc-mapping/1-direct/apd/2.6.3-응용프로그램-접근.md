# 2.6.3 응용프로그램 접근

> **기준 판본**: [KISA ISMS-P 인증기준 안내서(2023.11.23)](https://www.isms-p.or.kr/ntcn/rcsrm/selectGnrlRcsrmList.do).
> **관련 법령**: 2026-07-26 기준.
> **내용 구분**: §1은 KISA 안내서와 법령을 요약했다. §3~§4에는 작성자의 실무 경험을 반영했다.

## 1. ISMS-P 기준 요약

### 인증기준
사용자의 업무와 접근 정보의 중요도에 따라 응용프로그램 접근권한을 제한하고, 불필요한 정보와 중요정보의 노출을 최소화할 수 있는 기준을 수립·적용하여야 한다.

### 주요 확인사항 (KISA 안내서)
1. 사용자의 업무에 따라 응용프로그램 접근권한을 차등 부여하고 있는가?
2. 일정 시간 입력이 없는 세션을 자동 차단하고 동일 사용자의 동시 세션 수를 제한하고 있는가?
3. 관리자 전용 응용프로그램은 비인가자가 접근하지 못하도록 통제하고 있는가?
4. 개인정보와 중요정보의 표시 제한을 일관되게 적용할 수 있는 기준을 수립·적용하고 있는가?
5. 조회·화면표시·인쇄·다운로드 등에서 개인정보와 중요정보의 불필요한 노출을 최소화하고 있는가?

### 관련 법규
- 개인정보 보호법 제29조 (안전조치의무)
- 개인정보의 안전성 확보조치 기준 제5조 (접근권한의 관리), 제6조 (접근통제), 제12조 (출력·복사 시 안전조치)

### 핵심 통제 (KISA 안내서)
- 응용프로그램 접근권한 분류·부여 기준 수립
- 역할(Role) 기반 접근통제 — 직무별 메뉴·트랜잭션·데이터 수준 차등
- 사용자 인증·세션 타임아웃·동시 접속 제한
- 관리자 전용 페이지·콘솔 접근 제한
- 개인정보 마스킹 기준의 일관된 적용
- 개인정보 조회·표시·인쇄·다운로드의 최소화

### 결함사례 (KISA 안내서)
- **사례 1**: 권한 제어 오류로 열람 권한이 없는 사용자에게 개인정보가 노출됨
- **사례 2**: 외부에 공개된 관리자 페이지에 안전한 인증수단을 적용하지 않음
- **사례 3**: 타당한 사유 없이 세션 타임아웃이나 동일 계정의 동시 접속 제한을 적용하지 않음
- **사례 4**: 다운로드 파일에 업무상 불필요한 개인정보가 과도하게 포함됨
- **사례 5**: 과도한 유사검색을 허용하여 사용자가 업무 범위를 넘는 개인정보를 조회할 수 있음
- **사례 6**: 동일 개인정보 항목에 화면별로 서로 다른 마스킹 기준이 적용됨
- **사례 7**: 화면에는 마스킹했지만 웹페이지 소스에서 원문 개인정보가 노출됨

## 2. ITGC 매핑

| 항목 | 값 |
|---|---|
| 분류 | 직접 (1-direct) |
| ITGC 영역 | APD (Access to Programs and Data) |
| 부영역 | — |
| 보조 영역 | ITAC (SoD = APD + ITAC 교차), 2.5.1 (계정 라이프사이클), 2.5.6 (권한 검토) |

## 3. IT감사에서는 이렇게

### 3-A. 한국 비금융 ITGC 실무 적용

**2.6.3은 접근권한 관리와 개인정보 노출 최소화를 함께 다룬다.** 접근권한 부분은 APD 절차와 겹치고 세션·마스킹·출력 통제는 재무보고 위험과 관련된 범위만 ITGC에서 다룬다.

| ISMS-P 요구사항 | ITGC 검증 위치 | 비고 |
|---|---|---|
| 업무별 접근권한 차등 부여 | **2.5.1** 사용자 계정 관리 / **2.5.5** 특수 계정 / **2.5.6** 접근권한 검토 | 감사 범위 내 응용프로그램의 사용자·역할·권한을 대조 |
| 미사용·동시 세션 제한 | **2.5.3** 사용자 인증 / 보안 설정 | 재무보고 위험과 관련된 경우 설정 검토에 포함 |
| 관리자 전용 응용프로그램 접근 제한 | **2.5.5** 특수 계정 / **2.6.1** 네트워크 접근 | 관리자 권한과 관리자 페이지 접근 경로를 함께 확인 |
| 마스킹 기준의 일관된 적용 | **개인정보 영역** / 응용프로그램 통제 | 재무보고 관련 핵심 정보에 영향이 있으면 관련 통제 검토 |
| 조회·인쇄·다운로드 노출 최소화 | **개인정보 영역** / 보안 모니터링 | 개인정보 및 중요정보 노출 위험을 중심으로 검토 |

**ITAC에서 권한 검토가 별도로 필요한 경우**:
- **SoD 충돌 식별 시** — ITGC에서 충돌 목록과 보완통제를 평가하고, 필요하면 거래 수준의 상세절차 또는 실증절차로 실제 처리 내역을 확인
- **자동화 통제(automated control) 의존 시** — 시스템이 강제하는 승인·검증 로직의 권한 설정이 우회 불가능한지 확인
- **Key report 생성 권한** — 재무 보고에 사용되는 시스템 리포트(IPE)의 생성·수정 권한자 적정성
- **재무적 민감 영역의 권한 분리** — 재무·자금·구매 등 횡령·부정 위험이 높은 프로세스에서 입력/승인/실행 권한이 동일인에게 집중되지 않았는지 (예: 자금 이체 요청자 ≠ 승인자, 매입 등록자 ≠ 지급 실행자)

ISMS-P 인증심사에서는 독립 기준으로 평가한다. ITGC에서는 기존 접근권한 감사조서로 충족되는 부분을 교차참조하고, 세션·관리자 페이지·정보 노출 중 감사 범위와 관련된 사항을 보완한다.

### 3-B. ISMS-P 추가 요구사항 중 일반 ITGC 범위 밖

| ISMS-P 요구사항 | 절차 | 주된 담당 영역 |
|---|---|---|
| 세션 타임아웃·동시 접속 제한 | 애플리케이션 보안 설정 점검 | **보안 설정** (ITGC에서는 형식 확인 수준) |
| 개인정보 마스킹·비식별화 | 화면·출력물 개인정보 노출 여부 | **개인정보 영역** (3장) |
| 대량 다운로드 통제·모니터링 | 건수 기준·알림·차단 설정 | **보안 모니터링** (SOC·정보보안팀) |
| 출력·다운로드 노출 최소화 | 출력 항목·권한·기록 및 불필요한 정보 포함 여부 확인 | **개인정보·보안 영역** |

## 4. Q&A

### Q1. 한국 비금융 ITGC 실무, 2.6.3 별도로 봐야 함?

A. **접근권한은 기존 APD 절차와 교차참조하고, 나머지 요구사항은 감사 범위와 위험에 따라 보완한다.**
- **계정·권한 적정성** → 2.5.1/2.5.5에서 감사 범위 내 응용프로그램의 사용자 마스터 추출·대조
- **역할 설계·권한 차등·SoD** → 2.5.6 정기 검토에서 역할 매핑·충돌 식별 이미 수행
- **SoD 충돌의 영향** → 필요 시 거래 수준의 상세절차 또는 실증절차 수행
- **세션·관리자 페이지·정보 노출** → 재무보고 위험과 관련된 사항을 추가 검토
- 기존 감사조서에 교차참조를 남기고 ISMS-P 심사 증적은 기준별로 식별

### Q2. 세부 주제는 어디서 보나?

A. **2.6.3에서 흔히 묻는 주제들이 다른 인증기준에 이미 있다.**

| 주제 | 검증 위치 |
|---|---|
| 과다 권한·특수 권한 (SAP_ALL 등) | **2.5.5** 특수 계정 및 권한 관리 |
| 역할 정의서·권한 매트릭스 검증 | **2.5.6** 접근권한 검토 |
| SoD 매트릭스·충돌 식별 | **2.5.6** + **ITAC** |
| 퇴직·전보 후 권한 미회수 | **2.5.1** 사용자 계정 관리 |
| 세션 타임아웃·인증 강화 | **보안 설정** (일반 ITGC 범위 밖인 경우가 많음) |
| 개인정보 마스킹·대량 다운로드 | **보안 모니터링** (일반 ITGC 범위 밖인 경우가 많음) |

## 관련 인증기준
- 2.5.1 사용자 계정 관리 (계정 라이프사이클 — 계정 보유자가 적절한가)
- 2.5.5 특수 계정 및 권한 관리 (SAP_ALL·sysadmin 등 과다 권한)
- 2.5.6 접근권한 검토 (정기 검토 사이클·증적)
- 2.6.4 데이터베이스 접근 (DB 직접접근은 별도)
- 2.8.3 시험과 운영 환경 분리 (환경 분리를 통한 접근 통제)
- 2.9.4 로그 및 접속기록 관리 (접근 로그 보존·검토)

## 관련 법규·기준·표준
- 개인정보의 안전성 확보조치 기준 제5조 (접근권한의 관리)
- COBIT 2019 DSS05.04 (Manage Identity and Logical Access)
- ISO/IEC 27002:2022 5.18 (Access rights), 8.3 (Information access restriction)
