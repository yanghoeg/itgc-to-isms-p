# 2.6.2 정보시스템 접근

> **기준 판본**: [KISA ISMS-P 인증기준 안내서(2023.11.23)](https://www.isms-p.or.kr/ntcn/rcsrm/selectGnrlRcsrmList.do).
> **관련 법령**: 2026-07-26 기준.
> **내용 구분**: §1은 KISA 안내서 및 법령의 요약, §3~§4은 작성자의 실무 경험에 기반한다.

## 1. ISMS-P 기준 요약

### 인증기준
서버·네트워크시스템 등 정보시스템에 접근할 수 있는 사용자, 접근 제한 방식, 안전한 접근수단을 정의하여 통제하여야 한다.

### 주요 확인사항 (KISA 안내서)
1. 정보시스템별 운영체제에 접근할 수 있는 사용자, 위치, 수단을 정의하여 통제하고 있는가?
2. 정보시스템 접속 후 일정 시간 업무를 처리하지 않으면 자동으로 접속을 차단하고 있는가?
3. 정보시스템의 사용 목적과 관계없는 서비스를 제거하고 있는가?
4. 주요 서비스를 제공하는 정보시스템을 독립된 서버로 운영하고 있는가?

### 관련 법규
- 개인정보 보호법 제29조 (안전조치의무)
- 개인정보의 안전성 확보조치 기준 제6조 (접근통제)

### 핵심 통제 (KISA 안내서)
- 운영체제 접근 허용 사용자·위치·수단 정의
- 전용 단말·IP 제한, 안전한 프로토콜 등 접근수단 적용
- 일정 시간 미사용 세션의 자동 차단
- 불필요한 서비스·포트 제거
- 주요 서비스의 독립 서버 운영

### 결함사례 (KISA 안내서)
- **사례 1**: 원격 터미널 세션에 타임아웃이 없어 장시간 미사용 상태에서도 접속이 유지됨
- **사례 2**: 서버 간 접근 제한이 미흡하여 인가된 서버를 경유해 다른 비인가 서버에도 접근할 수 있음
- **사례 3**: 보완대책 없이 Telnet·FTP 등 안전하지 않은 프로토콜과 불필요한 포트를 사용함
- **사례 4**: 서버 접근제어시스템을 우회해 서버에 접속할 수 있는 경로가 존재함

## 3. IT감사에서는 이렇게

### 3-A. 한국 비금융 ITGC 실무 적용

**2.6.2의 여러 요구사항은 기존 APD·네트워크 통제 또는 보안 설정 검토와 교차된다.** 따라서 별도 통제를 중복 설계하기보다 기존 감사절차가 네 가지 확인사항을 빠짐없이 다루는지 확인한다.

| ISMS-P 요구사항 | ITGC 검증 위치 | 비고 |
|---|---|---|
| 허용 사용자·위치·접근수단 | **2.5.1** 사용자 계정 관리 / **2.5.5** 특수 계정 / **2.6.1** 네트워크 접근 | 서버 운영체제 계정과 허용 IP·경로·프로토콜을 함께 확인 |
| 미사용 세션 자동 차단 | **2.5.3** 사용자 인증 / 시스템 보안 설정 | 재무보고 위험과 관련된 경우 설정 검토에 포함 |
| 불필요 서비스 제거 | **보안 진단** | 일반적으로 취약점 점검·보안 강화 영역 |
| 주요 서비스의 독립 서버 운영 | **시스템 아키텍처·운영 검토** | 중요도와 위험에 따른 논리·물리 분리 및 보완대책 확인 |

ISMS-P 인증심사에서는 독립 기준으로 평가한다. ITGC에서는 기존 감사조서가 위 요구사항을 충분히 다루면 교차참조할 수 있고, 다루지 못한 항목만 추가 절차를 수행한다.

### 3-B. ISMS-P 추가 요구사항 중 일반 ITGC 범위 밖

| ISMS-P 요구사항 | 절차 | 주된 담당 영역 |
|---|---|---|
| 불필요 서비스·포트 비활성화 | OS·장비 보안 강화 설정 점검(Telnet·FTP·미사용 포트) | **보안 영역** (보안 진단·취약점 점검) |
| 콘솔(물리) 접근 통제 | 서버룸 출입 + 콘솔 잠금장치 | **물리 보안** (2.4.x) |
| 보안장비(IPS·IDS·WAF) 접근 통제 | 보안장비 관리자 접근 제한 | **보안 영역** (SOC·정보보안팀) |
| 네트워크장비 접근 통제 | 스위치·라우터 관리 인터페이스 접근 | **보안 영역** (네트워크 운영팀) |

**범위 차이**: ISMS-P는 서버·네트워크장비·보안장비를 포괄한다. ITGC는 재무보고 시스템과 관련 기반 장비가 재무보고 위험에 미치는 영향을 기준으로 범위를 정하므로, 일반 보안장비 설정은 정보보호 점검에서 다루는 경우가 많다.

## 4. Q&A

### Q1. 한국 비금융 ITGC 실무, 2.6.2 별도로 봐야 함?

A. **기존 절차로 충족되는지 먼저 확인하고, 누락된 요구사항만 보완한다.**
- **서버 계정·권한** → 2.5.1/2.5.5에서 OS 사용자 마스터를 이미 추출·대조
- **접근 IP·경로·방화벽** → 2.6.1의 네트워크 접근 검증과 교차참조
- **세션 자동 차단** → 2.5.3 또는 시스템 보안 설정 검토와 교차참조
- **불필요 서비스·주요 서비스 분리** → 보안 진단과 아키텍처 검토 결과 확인
- 기존 감사조서에 위 교차참조를 명시하고, ISMS-P 심사 목적의 증적 식별은 별도로 관리

### Q2. 세부 주제는 어디서 보나?

A. **2.6.2에서 흔히 묻는 주제들이 다른 인증기준에 이미 있다.**

| 주제 | 검증 위치 |
|---|---|
| Jump server 우회 경로 차단 | **2.6.1** 방화벽 룰 (jump server IP 외 허용 건 식별) |
| 클라우드 서버 접근 (Security Group·IAM) | **2.6.1** Q2 (클라우드 네트워크 통제) |
| DB 직접접근 (SQL*Plus·SSMS 등) | **2.6.4** 데이터베이스 접근 |
| 콘솔(물리) 접근 | **2.4.x** 물리 보안 |
| 개발·운영 환경 분리 | **PD** (2.8.x) / **PC** (2.9.1) |
| 서버 보안 강화(불필요 포트·서비스) | **보안 진단** (일반 ITGC 범위 밖인 경우가 많음) |

## 관련 인증기준
- 2.5.1 사용자 계정 관리 (서버 계정 라이프사이클)
- 2.5.5 특수 계정 및 권한 관리 (root·Administrator 통제)
- 2.6.1 네트워크 접근 (네트워크 분리·방화벽과 연계)
- 2.6.4 데이터베이스 접근 (DB 직접접근은 별도)
- 2.6.6 원격접근 통제 (VPN·점프 서버 세부)
- 2.9.4 로그 및 접속기록 관리 (서버 접속 로그)

## 관련 법규·기준·표준
- 개인정보의 안전성 확보조치 기준 제6조 (접근통제)
- CIS Benchmarks (OS별 보안 강화 기준) — 일반적으로 보안 진단에서 참조
- NIST SP 800-123 (Guide to General Server Security)
- ISO/IEC 27002:2022 8.2 (Privileged access rights), 8.3 (Information access restriction)
