# 2.6.1 네트워크 접근

> **기준 판본**: [KISA ISMS-P 인증기준 안내서(2023.11.23)](https://www.isms-p.or.kr/ntcn/rcsrm/selectGnrlRcsrmList.do).
> **관련 법령**: 2026-07-26 기준.
> **내용 구분**: §1은 KISA 안내서 및 법령의 요약, §3~§4은 작성자의 실무 경험에 기반한다.

## 1. ISMS-P 기준 요약

### 인증기준
네트워크에 대한 비인가 접근을 통제하기 위하여 **IP관리, 단말인증 등 관리절차를 수립·이행**하고, 업무목적 및 중요도에 따라 **네트워크 분리(DMZ, 서버팜, DB존, 개발존 등)와 접근통제**를 적용하여야 한다.

### 주요 확인사항 (KISA 안내서)
1. 조직의 네트워크에 접근할 수 있는 **모든 경로를 식별**하고 내부 네트워크는 인가된 사용자만 접근하도록 통제하고 있는가?
2. 서비스·사용자 그룹·자산 중요도·법적 요구사항에 따라 네트워크 영역을 **물리적 또는 논리적으로 분리**하고 영역 간 접근통제를 적용하고 있는가?
3. 네트워크 대역별 **IP주소 부여 기준**을 마련하고 외부 연결이 필요하지 않은 경우 **사설 IP**로 할당하고 있는가?
4. 물리적으로 떨어진 IDC·지사·대리점 등과의 연결 시 **전송구간 보호대책**을 마련하고 있는가?

### 관련 법규
- 개인정보 보호법 제29조 (안전조치의무)
- 개인정보의 안전성 확보조치 기준 제6조 (접근통제)

### 접근통제 영역 (KISA 안내서 6개)

| 영역 | 적용 예시 |
|---|---|
| **DMZ** | 외부 서비스용 웹·메일 서버. DMZ 경유 안 한 인터넷 → 내부 직접 연결 차단 |
| **서버팜** | 다른 영역과 구분 + 인가 내부 사용자만 접근 |
| **DB존** | 개인정보·중요정보 DB는 다른 영역과 분리 |
| **운영자 환경** | 서버·보안장비·네트워크 장비 운영자 네트워크 = 일반 사용자와 분리 |
| **개발 환경** | 개발·테스트 네트워크 = 운영 네트워크와 분리 |
| **외부자 영역** | 외주·민원실·교육장 등 외부 인력 네트워크 = 내부 업무망과 분리 |

**기타**:
- 업무망 = 특성·중요도에 따라 대역 분리
- 클라우드 = 클라우드 특성 반영
- 회사 규모상 서버팜·DB팜 분리 어려우면 → 위험평가 + 보완대책 (호스트 기반 접근통제)

### IP 관리 (KISA 안내서)
- IP 할당 현황 최신 유지 + **대외비 이상 관리**
- 내부망 = 사설 IP (RFC 1918) + NAT 적용
- 사설 IP 대역: A 10.0.0.0/8, B 172.16.0.0/12, C 192.168.0.0/16

### 전송구간 보호 (KISA 안내서)
- IDC·지사·대리점·협력업체·고객센터 연결 시 **전용회선 또는 VPN**

### 결함사례 (KISA 안내서)
- **사례 1**: 외부 지점과 IDC 서버 연결에 **VPN이나 전용회선 없이 일반 인터넷 회선**을 사용함
- **사례 2**: 중요 서버에 규정과 달리 **공인 IP를 할당하고 접근을 차단하지 않음**
- **사례 3**: 서버팜 구성됐지만 접근제어 미흡 → **내부망 → 서버팜 과도 허용**
- **사례 4**: 외부자 네트워크를 내부 업무망과 분리하거나 별도로 통제하지 않음
- **사례 5**: MAC 인증이나 필수 보안 소프트웨어 확인 없이 **네트워크 케이블 연결만으로 사내망에 접근**할 수 있음

## 3. IT감사에서는 이렇게

### 3-A. 한국 비금융 ITGC 실무 적용

**핵심 원칙: 재무보고 범위에 포함된 시스템과 그 시스템으로 이어지는 접근 경로를 위험기반으로 검증한다.**

- 웹 서비스·DMZ·외부 접속·SaaS 연계 등 외부 노출은 위험을 높이는 중요한 고려사항이다.
- 외부 노출이 없더라도 내부 사용자, 외부자, 지사, 관리망 또는 다른 시스템을 통한 접근 경로가 있으면 관련 통제를 검토할 수 있다.
- 외부 노출 자산이라도 재무보고와 무관하고 감사 범위 내 시스템으로 이어지는 경로가 없다면 일반 정보보호 영역에서 다루는 것이 통상적이다.

> 재무보고 범위 밖 자산이 감사 범위 내 시스템과 같은 네트워크 구간에 있거나 이를 경유해 접근할 수 있다면, 내부 확산 위험을 고려하여 네트워크 분리와 접근통제를 ITGC 범위에 포함할 수 있다.

| ISMS-P 요구사항 | ITGC 테스트 절차 | 모집단 | 표본 |
|---|---|---|---|
| 1. 네트워크 구성도 | 네트워크 구성도와 DMZ·서버팜·DB존·개발/운영 분리 현황 확인 | 최신 구성도 | 워크스루 및 구성 확인 |
| 2. 방화벽 규칙 | 방화벽 규칙 목록과 영역 간 차단 정책 검증(특히 외부에서 내부로의 직접 연결) | 관련 규칙 전체 | 규칙 기반 검토 |
| 3. IP 관리 대장 | IP 할당 현황과 외부 연결이 불필요한 시스템의 사설 IP 사용 여부 검증 | IP 관리 대장 | 규칙 기반 검토 |
| 4. VPN·전용회선 | 외부 지점·외주·재택 접속 시 VPN/전용회선 적용 + 사용 로그 | 외부 접속 경로 전체 | 100% |
| 5. 방화벽 규칙 변경 통제 | 규칙 변경 신청·승인·적용 이력 확인(변경관리 통제와 연계) | 관련 규칙 변경 전체 | 감사계획에 따른 표본 |

### 3-B. ISMS-P 추가 요구사항 중 일반 ITGC 범위 밖

| ISMS-P 요구사항 | 절차 | 주된 담당 영역 |
|---|---|---|
| 단말 인증 (NAC·MAC 인증) | NAC 운영 정책·예외 처리 | **보안 영역** (NAC 운영) |
| 불필요 서비스·포트 차단 | 네트워크 장비 보안 강화 설정 점검 | **보안 영역** (보안 진단) |
| 침입차단시스템 ACL 상세 검토 | IDS·IPS 룰셋 검증 | **보안 영역** (SOC) |
| 클라우드 환경 접근통제 (Security Group·VPC) | 클라우드 IAM·SG 정책 | **보안 영역** + 클라우드 ITGC (별도 영역) |

## 4. Q&A

### Q1. 회사에 네트워크 분리·VPN 정책이 없으면 ITGC 결함인가?
A. **정책의 명칭이나 외부 노출 여부만으로 단정하지 않고, 재무보고 시스템의 접근 경로와 위험에 맞는 통제가 있는지 평가한다.**
- 외부 접속 경로가 없다면 VPN 통제가 필요하지 않을 수 있다. 다만 내부 접근 경로, 지사 연결, 외부자 접속 등 실제 경로는 확인해야 한다.
- 외부 접속 경로가 있다면 허용 대상·수단·구간 보호와 변경 통제가 위험에 맞게 설계·운영되는지 검토한다.
- 결함 여부와 중요도는 통제 부재가 재무보고 위험에 미치는 영향, 대체통제 및 발견된 예외를 함께 고려해 판단한다.

### Q2. 클라우드 환경 (AWS·Azure·GCP) — 2.6.1 어떻게 적용?
A. **클라우드에서는 Security Group·VPC·IAM 등 클라우드 고유 통제로 매핑한다.**
- **클라우드 ITGC 별도 검증 영역**:
  - VPC·Subnet 분리 (DMZ·서버팜·DB존 매핑)
  - Security Group·NACL 룰 검토
  - IAM 정책 (네트워크 ACL 변경 권한 분리)
  - VPN·Direct Connect·Transit Gateway 구성
  - 공개 서브넷에 데이터베이스가 불필요하게 노출되지 않았는지 확인
- 온프레미스 환경과 달리 클라우드는 서버팜·DB존을 VPC·서브넷·보안그룹 등으로 논리적으로 분리하는 경우가 많으므로 해당 구성을 검증한다.

### Q3. 한국 비금융 ITGC 실무, 2.6.1 어디까지 봐야 함?
A. **재무보고 범위와 접근 경로를 기준으로 검증 범위를 정한다.**
- 외부 노출 자산과 내부 접근 경로를 식별하고 재무보고 시스템과의 연결성을 평가
- 핵심은 ① 구성도, ② 방화벽 룰, ③ VPN, ④ IP 관리, ⑤ 변경 통제의 5가지다.
- 단말 인증·NAC·IPS 룰셋·장비 보안 강화는 재무보고 위험과 직접 관련되지 않으면 일반적으로 **보안 영역**에서 검토
- 클라우드는 온프레미스와 다른 논리적 네트워크 구성과 관리 권한을 반영하여 검증
