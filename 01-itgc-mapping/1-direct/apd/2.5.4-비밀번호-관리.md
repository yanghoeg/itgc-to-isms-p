# 2.5.4 비밀번호 관리

> **기준 판본**: [KISA ISMS-P 인증기준 안내서(2023.11.23)](https://www.isms-p.or.kr/ntcn/rcsrm/selectGnrlRcsrmList.do).
> **관련 법령**: 2026-07-26 기준.
> **내용 구분**: §1은 KISA 안내서와 법령을 요약했다. §3~§4에는 작성자의 실무 경험을 반영했다.

## 1. ISMS-P 기준 요약

### 인증기준
법적 요구사항, 외부 위협요인 등을 고려하여 **정보시스템 사용자 및 고객, 회원 등 정보주체(이용자)가** 사용하는 **비밀번호 관리절차를 수립·이행**하여야 한다.

### 주요 확인사항 (KISA 안내서)
1. 정보시스템에 대한 안전한 사용자 비밀번호 관리절차 및 작성규칙을 수립·이행하고 있는가?
2. 정보주체(이용자)가 안전한 비밀번호를 이용할 수 있도록 비밀번호 작성규칙을 수립·이행하고 있는가?
3. 개인정보취급자 또는 정보주체의 인증수단을 안전하게 적용하고 관리하고 있는가?

### 관련 법규
- 개인정보 보호법 제29조 (안전조치의무)
- 개인정보의 안전성 확보조치 기준 제5조 (접근권한 관리)

### 비밀번호 작성규칙 (KISA 안내서, 시스템을 통한 강제 적용 권고)

| 구분 | 내용 |
|---|---|
| **조합 규칙** | 영문·숫자·특수문자 중 **2종류 이상 조합, 최소 8자리** / 문자만 구성 시 **최소 10자리**(숫자로만 구성하지 않도록 유의) |
| **변경주기** | 유효기간과 주기적 변경 여부는 **위험평가 결과를 고려하여 자체 결정** |
| **추측 쉬운 비밀번호 제한** | 동일 문자 반복, 키보드 나란히 문자열, 일련번호·연속 숫자, 생일·전화번호 등 개인정보, ID와 비슷한 비밀번호 사용 제한 |
| **재사용 제한** | 변경 시 이전 비밀번호 재사용 제한 |

### 비밀번호 관리절차 (KISA 안내서 예시)
- 시스템 도입 시 초기/임시 비밀번호 변경 후 사용
- 비밀번호 입력·변경 시 마스킹 처리
- 종이·파일·모바일 기기 비밀번호 기록·저장 제한 (부득이한 경우 암호화)
- 침해사고 발생 또는 노출 의심 시 지체 없이 변경
- 비밀번호 분실 재설정 시 본인확인 절차
- 관리자 비밀번호는 비밀정보에 준하여 관리

### 비밀번호 외 인증수단 (제5조제5항)
- 인증서·PIN·생체인식·보안토큰 등에는 탈취·도용 방지대책 적용

### 결함사례 (KISA 안내서)
- **사례 1**: 정책에 비밀번호 생성규칙을 정해놓았으나 **일부 시스템에서 내부 지침과 상이한 비밀번호** 사용
- **사례 2**: 비밀번호 초기화 시 임시 비밀번호를 부여받고 **강제적으로 변경하도록 되어 있으나 실제로는 임시 비밀번호를 그대로 사용**
- **사례 3**: 비밀번호 변경주기를 정하고 이행하도록 했음에도 **변경하지 않고 그대로 사용**

### 3-A. 한국 비금융 ITGC 실무 적용

비밀번호 정책은 2.5.3 영역(실패횟수·세션 타임아웃)과 한 화면에 같이 나오므로 보통 **하나의 자동통제 캡처로 동시 검증**한다.

| ISMS-P 요구사항 | ITGC 테스트 절차 | 모집단 | 표본 |
|---|---|---|---|
| 1. 비밀번호 작성규칙 | 시스템 설정값 캡처 (길이·복잡도·금지 패턴) | 전 시스템 | 시스템별 설정 확인 + 대표 1건 재수행 |
| 2. 비밀번호 변경주기 | 시스템 설정값 캡처 (유효기간 일수, 회사 정책과 일치) | 전 시스템 | 시스템별 설정 확인 + 대표 1건 재수행 |
| 3. 재사용 제한 | 시스템 설정값 캡처 (최근 N개 비밀번호 재사용 차단) | 전 시스템 | 시스템별 설정 확인 + 대표 1건 재수행 |
| 4. 임시 비밀번호 강제 변경 | 신규 계정·재설정 계정에 첫 로그인 시 비밀번호 변경 강제 | 전 시스템 | 시스템별 설정 확인 + 대표 1건 재수행 |
| 5. 정책 문서 | 회사 비밀번호 정책 문서 | 정책 1건 | 워크스루 1건 |

## 4. Q&A

### Q1. 비밀번호 변경주기 90일·분기 무조건 강제인가? 비금융에도?
A. **일반 비금융 개인정보처리자에게 일률적으로 분기·90일 변경을 강제하는 개인정보 보호 법령은 없다.** 금융권·공공기관 등에는 별도 업권 규정이나 내부 기준이 적용될 수 있으므로 적용대상을 먼저 확인한다.

**한국 법령·표준별 변경주기 강제 여부**:

| 법령/표준 | 변경주기 강제 |
|---|---|
| 개인정보의 안전성 확보조치 기준 제5조 | 인증수단의 안전한 적용·관리를 요구하며 획일적인 변경주기 숫자는 두지 않음 |
| KISA ISMS-P 인증기준 안내서 (2023.11) | 위험평가를 고려해 주기적 변경 여부와 주기를 자체 결정 |
| 개인정보 보호법·시행령 | 획일적인 변경주기를 정하지 않음 |
| 현행 일반 개인정보 보호 법령 | 모든 개인정보처리자에게 적용되는 획일적인 6개월 변경주기 없음 |
| **전자금융감독규정 제32조** | **내부사용자 비밀번호 분기별 1회 이상 변경 (금융회사·전자금융업자 한정)** |

따라서 금융권 규정을 일반 비금융 회사에 그대로 적용하여 분기 변경을 의무라고 단정해서는 안 된다.

**KISA 안내서(2023.11) 요지**: 비밀번호 유효기간과 주기적 변경 여부는 위험평가 결과 등을 고려하여 조직이 결정한다.

**배경**: NIST SP 800-63B는 정기적인 일괄 변경보다 비밀번호 유출·침해 징후가 있을 때 변경하도록 안내한다. 위험에 따라 변경 여부를 판단하는 방식이다. KISA 안내서도 변경 여부와 주기를 위험평가 결과에 따라 자체 결정하도록 안내한다.

**ITGC 결함 판단 기준 (회사 정책 + 일관성)**:
| 회사 정책 | 시스템 설정 | 결함 판단 |
|---|---|---|
| "분기 변경" 명시 | 분기 변경 적용 | 적정 |
| "분기 변경" 명시 | 무제한 | **결함** (정책-실제 불일치) |
| "위험평가 결과 자율" | 주기적 변경 없음 + 보완통제(긴 비밀번호·MFA·로그 모니터링) | 위험평가 근거 확인 후 판단 |
| 정책 자체 부재 | 주기적 변경 없음 + 보완통제 없음 | **결함** (전사 수준 정책 부재) |

**핵심**: 일반 비금융 회사에 분기·90일 주기가 일률적으로 강제되는 것은 아니다. **회사 정책과 시스템 설정의 정합성**, 그리고 위험평가 근거를 함께 본다.

### Q2. 정책상 8자리인데 시스템은 6자리 — 결함?
A. **정책과 설정의 불일치이므로 결함으로 기록하고 영향을 평가한다.**
- 6자리 설정은 회사의 8자리 정책을 충족하지 못하고 통제 목적도 약화한다.
- KISA 결함사례도 일부 시스템이 내부 지침과 다른 비밀번호 규칙을 사용하는 경우를 제시한다.
- 미세 차이 (정책 9자리·시스템 8자리)도 **정책-설정 불일치 사실은 기록**하고 원인·영향을 평가
- **차이 판단 기준**: 통제 목적 달성 여부와 승인된 예외 존재 여부. 숫자 차이만으로 결함 등급을 기계적으로 정하지 않되, 불일치를 결함이 아니라고 단정하지 않음

### Q3. 임시 비밀번호 강제 변경 — 어디까지 검증?
A. **KISA 결함사례 2번에 해당하는 영역으로, 신규·재설정 계정의 대표 사례를 워크스루한다.**
- 검증 절차:
  - 신규 계정 발급 시 임시 비밀번호 부여 → 첫 로그인 시 변경 강제(시스템 설정 캡처 + 워크스루 1건)
  - 비밀번호 분실 재설정도 동일
- 시스템별 설정 적용범위 확인 + 대표 1건 재수행 + ITGC 일반통제 의존
- **결함 판단**:
  - 강제 변경 설정이 없음 → 결함(KISA 결함사례 2번)
  - 정책상 강제이지만 "임시 비밀번호 그대로 사용 중" 사례 발견 → 결함 (정책-실제 불일치)
  - 강제 변경 설정과 대표 사례가 모두 정상 → 적정

### Q4. 포스트잇·메신저 비밀번호 공유는 ITGC 결함인가?
A. **일반적으로 보안 진단·인사 영역에서 직접 점검한다. 다만 관련 정책·서약·교육 통제의 미비와 함께 발견되면 ITGC에도 영향을 줄 수 있다.**
- KISA 안내서: "종이·파일·모바일 기기 등 비밀번호 기록·저장 제한"
- ITGC에서는 정책 수립·보안 서약·인식 교육을 주로 확인하고, **포스트잇 등 책상 점검은 보안 진단·내부감사에서 수행**하는 경우가 많다.
- **연결 통제** (2.5.2 Q5 본인 사용 보장):
  - 비밀번호 공유 금지 정책(전사 수준) → 2.1 정책
  - 보안 서약서 작성 → 2.2.3
  - 인식 교육 → 2.2.4
  - 위반 시 조치 → 2.2.6
- **결함 판단**:
  - 일반 ITGC는 비밀번호 공유 정황을 직접 찾기 위한 책상 점검까지 수행하지 않는 경우가 많음
  - 다만 정책·서약·교육 자체가 부재 → 전사 수준 통제 미비 가능
  - 인터뷰에서 비밀번호 공유 정황 발견 + 정책·서약 부재 → 묶어서 결함

### Q5. 한국 비금융 ITGC 실무, 2.5.4 어디까지 봐야 함?
A. **§3-A의 5개 항목(작성규칙·변경주기·재사용 제한·임시 비밀번호 강제 변경·정책 문서)을 본다. 2.5.3과 한 캡처로 함께 검증한다.**
- 한 화면 (AD GPO·Linux PAM·DB 사용자 정책·web 인증 설정)에 비밀번호 작성규칙·변경주기·재사용 제한이 다 같이 나옴 → 2.5.3 (실패횟수·세션 타임아웃)과 묶어서 자동통제 1건 캡처
- 임시 비밀번호 강제 변경은 신규 계정 발급 사례 1건을 별도로 워크스루
- 정책 문서는 전사 수준 통제로 1건 검증
- B2C 회원가입 정책·포스트잇 점검·인증서 보호 등은 주로 ISMS-P 인증심사나 보안 영역에서 다룸
- 이는 회계감사 ITGC와 정보보안 영역의 역할을 나눈 결과다.
